# Что работает до домена и VPS

На временном Render уже можно полноценно проверять:

- регистрацию, вход, выход, восстановление пароля и изоляцию заказов;
- лимиты запросов для авторизации, регистрации, восстановления, профиля и заказов;
- каталог, категории, страны, операторов, товары, варианты, SEO-поля и изображения (URL/alt/порядок/основное);
- серверный поиск PostgreSQL по товарам, странам, операторам, категориям, SKU и вариантам с пагинацией и trigram-индексами;
- каталог с фильтрами по стране, оператору, категории, типу SIM, наличию, трафику, сроку и цене теперь выбирает товары и страницы в PostgreSQL, не загружая весь ассортимент в память;
- обработку заказов в Telegram: поиск, фильтры, страницы, подтверждение оплаты менеджером, выполнение, отмену, FAILED и REFUNDED;
- управление клиентами в Telegram: поиск, карточка, блокировка, отзыв сессий, экспорт и удаление аккаунта с сохранением учётной истории заказов;
- просмотр постраничного журнала критических действий администраторов через кнопку `📋 Журнал действий`;
- автоматическую очистку просроченных сессий, ссылок восстановления и старых записей ограничения запросов при каждом deploy;
- обезличенный журнал технических ошибок с агрегацией, сроком хранения 90 дней и просмотром через кнопку `⚠️ Ошибки` в Telegram;
- автоматическое Telegram-оповещение о первом критическом сбое каждого типа за сутки без повторного спама;
- обезличенный CSV-экспорт заказов и UTM-источников за выбранный период через раздел аналитики Telegram;
- сравнение заказов, оплат, конверсии и оборота с предыдущим равным периодом в Telegram-аналитике;
- новые оплаты учитываются в отчётах по фактической дате подтверждения, а не по дате создания заказа; для старых заказов дата оплаты восстанавливается из платёжных событий или журнала действий, если они есть;
- агрегированную аналитику внутреннего поиска с запросами без результатов в Telegram; сбор только после согласия, чувствительные строки скрываются;
- внутренний поиск учитывается после согласия даже без Google Analytics/Яндекс.Метрики; отчёты продаж по товарам и странам не смешивают суммы в разных валютах;
- статусы магазина, зависшие заказы, низкие остатки и health endpoint `/api/health`;
- UTM-источник, канал и кампания сохраняются в заказе и показываются менеджеру/в Telegram-аналитике;
- зашифрованную резервную копию по кнопке `🗄 Резервная копия` в Telegram или командой `pnpm db:backup`.

## Резервные копии

Копия не содержит ключи Render и шифруется AES-256-GCM. Ключ берётся из `BACKUP_ENCRYPTION_KEY`; если он не задан, используется `FULFILLMENT_ENCRYPTION_KEY`. Не отправляйте файл и ключ вместе.

Ежедневный workflow GitHub вызывает закрытый endpoint `/api/operations/backup`. Сервер создаёт согласованный снимок базы, расшифровывает его обратно, проверяет полный набор таблиц и пробует загрузить строки во временные таблицы с текущими типами и ограничениями PostgreSQL. Только успешно проверенный зашифрованный файл отправляется владельцу в Telegram. Для запуска нужны одинаковый `BACKUP_CRON_SECRET` в Render и GitHub Actions, а также `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_IDS` и ключ шифрования в Render. При необходимости получателя можно переопределить через `BACKUP_TELEGRAM_CHAT_ID`.

Проверка файла без изменений:

```text
set FULFILLMENT_ENCRYPTION_KEY=тот_же_ключ
pnpm db:restore путь\к\копии.json.enc
```

Фактическое восстановление требует отдельного целевого URL и явного флага `--confirm-empty-target`:

```text
set RESTORE_DATABASE_URL=postgres://адрес-пустой-тестовой-базы
pnpm db:restore путь\к\копии.json.enc --confirm-empty-target
```

Если целевая PostgreSQL совершенно пустая, скрипт сам создаст актуальную схему без стран, товаров и других тестовых данных, а затем загрузит резервную копию. Если в базе уже есть таблицы, они должны соответствовать копии и быть пустыми; частично подготовленная или заполненная база будет отклонена. Адрес по-прежнему не может совпадать с рабочим `DATABASE_URL`.

Пустую схему без восстановления можно подготовить отдельно:

```text
set RESTORE_DATABASE_URL=postgres://адрес-пустой-тестовой-базы
pnpm db:init:empty
```

Актуальные миграции в каталоге `drizzle` созданы для PostgreSQL; прежняя SQLite-история удалена. Полный тест аварийного восстановления следует выполнять на отдельной временной базе после каждого крупного изменения схемы и не реже одного раза в месяц. Telegram используется как независимое временное хранилище; после переноса на основной сервер архивы следует дополнительно складывать в версионируемое объектное хранилище с политикой хранения.

## Что намеренно ждёт домен/внешнюю инфраструктуру

- подтверждённый почтовый домен Resend и реальные письма;
- боевой crypto-провайдер и его webhook-секреты;
- API поставщика eSIM;
- перенос DNS, Search Console и финальная SEO-проверка нового домена;
- основное объектное хранилище резервных копий и ежемесячный тест восстановления на отдельной временной базе.
